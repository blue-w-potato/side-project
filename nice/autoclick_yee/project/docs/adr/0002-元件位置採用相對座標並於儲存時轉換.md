# 元件位置採用相對座標,並於儲存腳本時計算轉換

元件位置(循環點擊位置、拖曳起訖點、按住位置)需要能跨裝置、跨螢幕解析度依然正確重現。決定:使用者在編排畫面上操作的位置,於「儲存腳本」的當下,依照當時裝置的螢幕尺寸換算成相對於螢幕寬高的百分比後才寫入腳本資料;執行腳本時則反向以執行當下裝置的螢幕尺寸還原出實際點擊座標。

Status: accepted

Considered Options: 直接以絕對像素座標儲存 — 實作最簡單,但腳本換裝置或螢幕解析度改變後位置會失準,不採用。

Amendment: 原本這裡還有一項規則——腳本建立時記錄橫式/直式,啟動前比對裝置目前方向,不一致就阻擋啟動,理由是相對座標以寬高為基準換算,方向不符會導致座標錯位。後續決定整個移除「橫式/直式」這個屬性與對應的啟動前方向檢查,腳本不再記錄、也不限制建立/執行時的裝置方向,簡化這部分的使用限制。因此原本的建立腳本流程(需先選橫式或直式)、`ScriptRecord.orientation` 欄位、Room 資料庫的 orientation 欄位皆已移除(資料庫因此升版並採用 destructive migration,見 `Database.kt`)。
